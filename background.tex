\textit{\textbf{LLVM IR.}}
\llvm IR is a low-level intermediate representation for languages such as C, C++, and Rust,
which is also widely used in program analysis techniques (\eg symbolic execution and model checking).
%In the following, we describe the aspects of \llvm IR that are relevant for our development.
In this paper,
we focus on a subset of \llvm IR with memory operations, whose syntax is given in~\Cref{figure:llvm-syntax}.
We define the following types: integers, pointers, and arrays.\footnote{
Our implementation supports also \textit{struct} types, but we omit them here for simplicity.
}
Integers are represented as bit-vectors of type $\bvsort{w}$, where \textsf{w} denotes the bit width.
Pointer types ($\pointertypeof{\tau}$) are parameterized by an element type $\tau$.
Array types ($\arraytype{\tau}{n}$) are parameterized by an element type $\tau$ and a dimension $n$.
The \llvm reference~\cite{llvmref} defines the special values $\tundef$ and $\tpoison$,
which are used for compiler optimizations.
The $\tundef$ value represents an unspecified bit-pattern
and the $\tpoison$ value represents a value that arises from invalid operations (\eg invalid shift).
%When one of the operands of an operation is $\tpoison$,
%the result is either $\tpoison$ or undefined behavior.
We define $\Vals^{\bvsort{w}}$ as the set containing all bit-vectors of type $\bvsort{w}$, along with $\tundef$ and $\tpoison$.
Then, we define $\Vals$ as the union of $\Vals^{\bvsort{w}}$ over all $w$.

\textbf{\textit{Notations.}}
We denote by $\bvval{n}{w}$ a bit-vector of type $\bvsort{$w$}$ whose numerical value is $n$.
We denote by $|\tau|$ the size of the type $\tau$ in bytes.
We denote by $\zeroext{w}{\bvval{n}{w'}}$ ($\signext{w}{\bvval{n}{w'}}$) a function that returns a bit-vector of type $\bvsort{w}$, defined as follows:
if $w' < w$ it performs zero-extension (sign-extension),
if $w' > w$ it performs truncation,
and otherwise it returns $\bvval{n}{w'}$.

\textit{\textbf{LLVM Memory Model.}}
% TODO: mention address space
% TODO: add citation
Based on the \llvm reference~\cite{llvmref}, a \emph{data layout} specifies how data is to be laid out in memory.
%The data layout consists of a list of specifications,
%including endianness, alignment rules, \etc
In particular, it defines various properties related to pointers, such as \emph{pointer type} and \emph{index type}.
The pointer type specifies the integral type used to represent pointer values.
The index type specifies the integral type used for address calculations (\eg in the $\tgep$ instruction).
The size of the index type may not exceed the size of the pointer type.
An allocated object is a region in the address space reserved by an allocation operation,
such as \textsf{alloca}, a heap allocation (\eg \textit{malloc}), or a global variable definition.
An allocated object may not cross the unsigned boundary of the address space,
and its size may not exceed the largest signed integer representable by the index type.
% In addition, the index type also specifies the type used to represent the size of allocated objects.
%In the remainder of this paper,
We denote the bit-widths of the pointer and index types by \textsf{ptr} and \textsf{idx}, respectively,
and their corresponding integral types by \textsf{iptr} and \textsf{iidx}.

\textit{\textbf{SMT}}
%We consider quantifier-free first-order logic modulo the theory of bit-vectors and arrays (QFABV),
We consider the QFABV logic fragment, which is standard in symbolic execution.
The bit-vector theory defines the $\mathsf{BV}[w]$ sort, which is interpreted as the set $\{0{,}1\}^w$,
and it defines interpreted function symbols such as $\textit{bvadd}$.
The array theory defines the array sort $\arraysort{I}{V}$ parameterized by an index sort $I$ and a value sort $V$,
which is interpreted as a total map of the appropriate type.\footnote{
In our context, we assume that both $I$ and $V$ are bit-vector sorts.
}
It defines the interpreted function symbols \textit{select}, \textit{store}, and \textit{K}.
Semantically,
$\mathit{select}(a, i)$ returns the value stored at index $i$ in $a$,
$\mathit{store}(a, i, v)$ returns the array obtained from $a$ by updating the value at index $i$ to $v$,
and $K(v)$ returns a constant array that maps all the indices to $v$.
%A \emph{model} $m$ must map interpreted function symbols to their accepted functions over $\{0{,}1\}^w$.
As is typically done \SE engines,
we identify the $\Bool$ sort with $\mathsf{BV}[1]$,
such that $\true$ and $\false$ correspond to $1$ and $0$, respectively.

\textbf{\textit{Notations.}}
We denote by $m[t]$ the interpretation of the term $t$ in a model $m$.
We denote by $t_1\equiv t_2$ the assertion that $m[t_1] = m[t_2]$ for any model $m$.
A formula $\varphi$ is satisfiable, denoted by $\sat{\varphi}$, if there is a model $m$ such that $m[\varphi] = \true$.
A formula $\varphi$ is unsatisfiable, denoted by $\unsat{\varphi}$, if $m[\varphi] = \false$ for any model $m$.
We denote by $\bvzextfunc{w}$ ($\bvsextfunc{w}$) a function that performs zero-extension (sign-extension) or truncation to return a bit-vector of sort $\smtsort{w}$.
We denote by $\bvextractfunc{w}$ a function that performs truncation to return a bit-vector of sort $\smtsort{w}$.
We use $\arrayselect{a}{i}$ and $\arraystore{a}{i}{v}$ as shorthands for $\mathit{select}(a, i)$ and $\mathit{store}(a, i, v)$.
We denote by $\bvconst{w}{n}$ a constant bit-vector of sort $\smtsort{w}$ whose numerical value is $n$ (indicated in \textcolor{smtcolor}{blue} throughout the paper).
