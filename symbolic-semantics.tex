\section{Symbolic Semantics}
\label{sec:symbolic-semantics}

In this section,
we define our symbolic operational small-step semantics of \llvm IR based on the syntax in~\Cref{figure:llvm-syntax}.

\subsection{Symbolic Memory Modeling}
\label{sec:symbolic-memory-modeling}

First, we define the major components of our symbolic memory model.
At a high level, this model mirrors its concrete counterpart (\Cref{sec:memory-modeling}), while using SMT expressions instead of concrete values (\ie bit-vectors).

\begin{definition}
A symbolic memory object is defined as a tuple:
\[ \mobj{\addr}{\size}{\smtarray} \in \SymMemoryObjects \quad \quad \SymMemoryObjects \triangleq \pointertype \times \indextype \times \arraysort{\smtsort{\indexwidth}}{\smtsort{8}} \]
where $\addr$ is its base address, $\size$ is its size,
and $\smtarray$ is an SMT array that tracks the stored \emph{symbolic bytes} (\ie SMT expressions of sort $\smtsort{8}$).
A symbolic heap $\symmemory \in \SymHeaps$ is defined as a set of symbolic memory objects.
\end{definition}

%Now, we define the operations provided by the symbolic memory model:
%allocation, deallocation, read, and write.

The \emph{allocation} and \emph{deallocation} operations $\symallocate$ and $\symdeallocate$ mirror their concrete counterparts,
while operating over symbolic memory objects and heaps.

\ignore{

\[ \symallocate : \SymHeaps \times \bvsort{\indexwidth} \to \SymHeaps \times \bvsort{\pointerwidth}, \ \symdeallocate : \SymHeaps \times \SymMemoryObjects \to \SymHeaps \]
The function $\symallocate$ receives a symbolic heap $\symmemory$ and an allocation size $\size$,
and attempts to provide a symbolic memory object $\mobj{\addr}{\size}{\smtarray}$ that satisfies the following:
\begin{enumerate}
    \item $[\addr, \addr + \size)$ is fully contained within the address space (\ie $\addr < \addr + \size$)
    \item $[\addr, \addr + \size)$ does not overlap with address intervals of existing memory objects
    \item $s \geq 0$ and does not exceed the largest signed integer representable by the index type
\end{enumerate}
If such a symbolic memory object can be provided,
then the result is the tuple $\langle \symmemory \cup \mobj{\addr}{\size}{\smtarray}, \addr \rangle$.
Otherwise, the result is $\none$.
The SMT array $\smtarray$ is set to the constant array $\arrayconst{\arrayinitvalue}$.

The \emph{read} and \emph{write} operations are defined using these functions ($w$ is the bit-width of $\tau$):
\[ \symmoreadfunc{\tau} : \SymMemoryObjects \times \smtsort{\pointerwidth} \to \smtsort{w}, \ \symmowritefunc{\tau} : \SymMemoryObjects \times \smtsort{\pointerwidth} \times \smtsort{w} \to \SymMemoryObjects \]
The $\symmoreadfunc{\tau}$ function receives a memory object $\symmo$ and a pointer $p$.
First, it reads the consecutive $|\tau|$ cells starting from $p$ into a sequence of symbolic bytes.
Then, it deserializes them into a \textit{concat} expression of the appropriate sort.
%\paragraph{Write}
%The \emph{write} operation is defined using the following function:
%\[ \symmowritefunc{\tau} : \SymMemoryObjects \times \pointertype \times \smtsort{w} \to \SymMemoryObjects \]
The $\symmowritefunc{\tau}$ function receives a memory object $\symmo$ (\ie $\mobj{\addr}{\size}{\smtarray}$), a pointer $p$, and an SMT expression $e$.
First, it serializes $e$ into a sequence of symbolic bytes.
Then, it uses these symbolic bytes to create a new symbolic memory object $\mobj{\addr}{\size}{\smtarray'}$,
where $\smtarray'$ is obtained by extending $\smtarray$ with additional store expressions. % at the corresponding offsets.

The symbolic memory allocator operates linearly, similarly to the concrete memory allocator defined in~\Cref{sec:memory-modeling}.

\subsection{Symbolic Operational Small-Step Semantics}

In the following,
we define the symbolic state and the derivation rules of the symbolic operational small-step semantics.

\begin{definition}
\label{def:symbolic-state}
A symbolic state is a tuple $\symstate{\location}{\symlocalstore}{\symstack}{\symmemory}{\pc}$,
where $\location \in \Locs$ is a program location,
$\symlocalstore \in \SymStores$ is a symbolic store mapping variables to SMT expressions,
$\symmemory \in \SymHeaps$ is a symbolic heap,
and $\pc$ accumulates path constraints along the execution path.
\end{definition}

The symbolic evaluation semantics of expressions, denoted by $\evalexprty{e}{\symlocalstore}{\tau}$, mirrors the concrete evaluation semantics (\Cref{figure:expr-semantics}).
Here, however, $\sem{\toper^\tau}$ and $\sem{\tcast^{\tau\to\tau'}}$ are \emph{function symbols} that construct SMT expressions.

\Cref{figure:symbolic-semantics} defines the symbolic operational small-step semantics for memory-related instructions introduced in~\Cref{figure:llvm-syntax}.
In some of the derivation rules, we use the following definitions (where $\symmo \triangleq \mobj{\bvval{\addr}{\pointerwidth}}{\bvval{\size}{\indexwidth}}{\smtarray}$):
\[
\baseaddrcond(p, \symmo) \triangleq p = \bvconst{\pointerwidth}{\addr}
\quad
\rangecond(p, n, \symmo) \triangleq p < \bvadd{\pointerwidth}{p}{n} \land p \geq \bvconst{\pointerwidth}{\addr} \land \bvadd{\pointerwidth}{p}{n} < \bvadd{\pointerwidth}{\bvconst{\pointerwidth}{\addr}}{\bvconst{\pointerwidth}{\size}}
%\begin{array}{ll}
%\baseaddrcond(p, \symmo) & \triangleq p = \bvconst{\pointerwidth}{\addr} \\
%\rangecond(p, n, \symmo) & \triangleq p < \bvadd{\pointerwidth}{p}{n} \land p \geq \bvconst{\pointerwidth}{\addr} \land \bvadd{\pointerwidth}{p}{n} < \bvadd{\pointerwidth}{\bvconst{\pointerwidth}{\addr}}{\bvconst{\pointerwidth}{\size}}
%\end{array}
\]
Intuitively,
$\baseaddrcond$ encodes the fact that $p$ points to the base address of $\symmo$,
and $\rangecond$ encodes the fact that the interval $[p, p + n)$ is fully contained within the address interval of $\symmo$.

\textbf{\textit{Malloc.}}
Based on the symbolic memory model (\Cref{sec:symbolic-memory-modeling}),
the size of a symbolic memory object must be concrete.
However, as the allocation size $e$ can be evaluated into a symbolic expression,
we concretize it using an SMT model $m$ that satisfies the path constraints $\pc$.
Then, if $\symallocate$ (\Cref{sec:symbolic-memory-modeling}) succeeds,
we update the local store and the heap accordingly.
Otherwise, the result is undefined behavior.
Note that this rule may produce multiple derivations.

\textbf{\textit{Free.}}
When deallocating a symbolic pointer $p$,
we check if there exists an SMT model $m$ satisfying $\pc$ and a memory object $\symmo$ in the heap $\symmemory$ such that $m[p]$ points to the base address of $\symmo$.
If that is the case, we remove $\symmo$ from $\symmemory$ using $\symdeallocate$ (\Cref{sec:symbolic-memory-modeling}) and extend $\pc$ with the condition $\baseaddrcond(p, \symmo)$.
Otherwise, the result is undefined behavior.
This rule might have multiple derivations as well, since $p$ may point to multiple memory objects.

\textbf{\textit{Load and Store.}}
% TODO: mentions the assumptions about n?
When accessing $n$ bytes from a pointer $p$,
we check if there exists an SMT model $m$ satisfying $\pc$ and a memory object $\symmo$ in the heap $\symmemory$ such that the first $n$ addresses starting from $m[p]$ are within the address interval of $\symmo$.
If that is not the case, the result is undefined behavior.
Otherwise, we perform a read or write operation.
For a read operation,
we first call $\symmoreadfunc{\tau}$ (\Cref{sec:symbolic-memory-modeling}) to read the corresponding value from $\symmo$,
and then update the local store accordingly.
For a write operation,
we call $\symmowritefunc{\tau}$ (\Cref{sec:symbolic-memory-modeling}) to update the contents of $\symmo$ accordingly.
